# 0004: 趋势判档 epsilon 死区（TREND_EPS=1e-4）

- 日期: 2026-11-17
- 状态: **已定案（commit 7633cd2c，随 §15.236 部署 a3b80d8）**

## 决策

`rolling_predict` 的趋势判档引入死区常量 `TREND_EPS = 1e-4`
（`biz/sales.py:249`）：阈值比较由严格不等式改为

```python
t7  = "up" if w7  > w14 * (TREND_UP_RATIO + TREND_EPS) else \
      ("down" if w7  < w14 * (TREND_DOWN_RATIO - TREND_EPS) else "flat")
t14 = "up" if w14 > w28 * (TREND_UP_RATIO + TREND_EPS) else \
      ("down" if w14 < w28 * (TREND_DOWN_RATIO - TREND_EPS) else "flat")
```

即比值落在阈值 ±1e-4 内一律判“平”。`replenishment.py` 的补货箭头共用同一常量。

## 背景：恰好落在阈值上的 SKU 等级翻转

`DECIMAL(12,3)` 量化 + `rolling_predict` 严格不等式：物化表里存的是 3 位舍入后的
日销，比值恰好落在 1.15 / 0.85 上的 SKU，物化口径与降级直算口径判出的等级不一致。

`caliber_probe` 判据③“物化表 vs 降级直算”FAIL：n=9999，max=0.3357，6 行 >0.05。
翻转的 6 个 SKU，fused 差 0.10–0.34，最大 SKU-04010-J 0.3357。55 个 SKU 聚在
阈值 ±0.002 内，**只有 6 个恰好在阈值上的翻了**——问题不在“近阈值”，在“恰好等于阈值”。

## 被否掉的方案

| 方案 | 为什么不采用 |
|---|---|
| 只提精度到 `DECIMAL(12,6)` | 原 6 个修好了，却翻了**新的 SKU-05927-J**：r14/28 恰好 17/20=0.85，6 位舍入后比值变为 0.8499998，略低于 0.85，判“降”，fused 差 0.5738，判据③ max 从 0.3357 变成 0.5738。**任何固定精度都根除不了**——总有下一个比值恰好落在阈值上，舍入方向一变就翻 |
| 只调探针判据 | 改判据不改口径，是掩盖不是修复。物化表与直算的等级分裂还在，判据③改松了等于宣布“分裂可接受” |
| 接受为已知限制 | 判据③持续 FAIL，物化表与降级直算长期口径分裂；每次 caliber_probe 都要人工解释这 6 行，等于把口径 bug 常态化 |

## 为什么选 epsilon：上下界都有实测数，不是拍脑袋

| 界 | 取值与依据 |
|---|---|
| 下界 | 全量 254,435 行实测，6 位舍入造成的比值误差上界 **5.571e-06**（近阈值 1,348 对全部 ≤1e-5；近阈值行最小 ds 0.142857）。`1e-4` 是该上界的 **~18 倍**——盖得住舍入噪声 |
| 上界 | 有业务意义的最小档位差取 0.002（55 个 SKU 聚在阈值 ±0.002 内）。`1e-4` 是它的 **1/20**——只吞舍入噪声，不吞真实趋势 |

验算 SKU-05927-J：真比值 0.85，舍入后 0.8499998（误差 2e-7）；下阈值变为
0.8499，0.8499998 > 0.8499 判“平”，与直算一致。讽刺的是 3 位精度下这个 SKU 没翻——
提精度修旧翻新，正是“固定精度根除不了”的实证。

## 验证

- `caliber_probe matrix` 判据③：**4 项全过，FAIL 0 → PASS；n=9999，max=0.0000**，
  >0.05 的行 0（之前 6 行 max 0.3357 → 1 行 max 0.5738 → 0 行）；原 6 个漂移 SKU +
  SKU-05927-J 两边一致（SKU-05927-J 物化 fused 2.1762 = 直算 2.1762）。
- 波及面：阈值 ±0.002 内 300 行；等级变了 **12 行 = 6 个 SKU，全部向平靠拢，
  无一例反向翻转**；**告警判定翻转 0**（6 SKU × 全部 8–9 个库存组 × 周期
  {6,9,12,17} 全测；最近一例 SKU-07993-O 某组库存距安全线 1.8，该 SKU 安全线
  最大移动仅 0.87，其余裕度均在 56 以上）。
- 版本：`SCHEMA_VERSION` 27→28、`_FP_VER` 8→9（DEVELOPMENT.md §七点五 #22：等级口径变了，
  fused / 安全线 / 告警 / 补货箭头读模型输出全变）。
- `test_audit` **87/0** / `local_test` **889/0**；冒烟 15/16（仅已知品牌窗口项，未修）。

## 代价与已知限制

- **55 个近阈值 SKU 随数据漂移**：阈值 ±0.002 内 300 行，数据一变就可能有新的 SKU
  落进死区或滑出死区，等级跟着变。这是死区方案的固有代价，不是 bug——判据③
  （caliber_probe matrix）是守门员，漂移超了它会先报警。
- **阈值 ±1e-4 内一律判平是口径变更**：不是纯修 bug，是改了等级定义。`_FP_VER`
  8→9 已标记；任何读模型输出的下游（fused、安全线、告警、补货箭头）都要按新口径理解。
- `replenishment.py` 的箭头改动按“单一常量共用”设计做；若认为箭头应另起一轮，
  该文件可单独回退，判据③不受影响（它只依赖 `rolling_predict`）。
