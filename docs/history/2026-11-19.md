## §15.238 生产评估超时误杀：现象与根因（两层）

现象：生产 `/api/tasks` 里 6 条 `rule_eval` 失败任务签名完全一致——stage=eval、ch=0（jd）、chunks=1、rows=4000、
cursor=`SKU-04000-J`、error“任务超时(30 分钟无更新)——自动标记结束，请重新导入”，且 error/result 在创建后仅 ~27–39 秒
就写下。失败：2026-11-17 12:04（cron）、2026-11-19 04:04（cron）、2026-11-19 13:41:27 / 13:42:30 / 13:44:02 / 13:45:23
（dashboard 手动触发 4 次）。其间 4 次成功穿插（2026-11-17 22:18 耗时 37m24s、23:12 26m25s、2026-11-18 00:00 4m07s、
12:04 4m53s，均为 6 片 / 20000 行）——算力没问题，任务死在 chunk-1 → chunk-2 交接处。影响：2026-11-19 04:04 的每日
评估没跑完，当天告警没被例行刷新。

根因①（源头）：`cloud-functions/api/db.py` 连接池 `_acquire` 用 `ping(reconnect=True)` 验活——pymysql 在死连接上静默建新连接，
绕过建连工厂 `_connect_db_inner`，丢了 `SET time_zone='+08:00'`，该连接的 `NOW()` 按 TiDB 默认 UTC 落库。证据：失败任务的
`created_at` 字符串“2026-11-19T05:45:23”等于其 params `started` epoch 1795067124（= 北京时间 13:45:24）的 UTC 墙时间。
间歇性 = 写库连接是否曾被 ping 复活（serverless 冻结/空闲会断连）。

根因②（判定）：`routes/cron.py` `continue_tasks()` 拿 Python 北京时间字符串（`now_cn() - 30min`）与 DB 时间字符串做字符串比较；
UTC 口径写下的任务出生即显“8 小时前”，第一次接力驱动就被标 error + `abandon()`。同类另两处在 `routes/cleansing.py`：
`cleansing_status()` 驱动分支（30 分钟清洗超时）与 `finalizing` 恢复检查（5 分钟）。审计结论：全仓仅此 3 处——其余超时判定
均已 SQL 侧（`DATE_SUB` / `TIMESTAMPDIFF`）或带租约，同口径安全。

数据库侧北京时间对齐的思路落在两层：源头由建连工厂保证每条连接的时区，判定由 DB 在同一口径下算，
不再拿 Python 时间字符串去比。

## §15.242 订单页窄屏右侧空白竖条：浮动链接压窄表格容器（2026-11-19 根治）

现象：手机端订单页表格右侧出现整高空白竖条（393px 视口，京东渠道）；桌面宽屏无此现象。
根因（本地同代码部署 393px 实测 + 反事实验证）：卡片标题行内「查 1 年前」链接为 float:right；
窄屏下标题一行排满，链接被挤出标题行、向下溢出约 13px，压进下方 overflow:auto 的表格滚动
容器区域；该容器是 BFC、不能与浮动元素重叠，整高被压窄一个链接宽度（109px），容器由
329px 缩到 220px，右侧空出整高竖条。
修法：标题行 div 加 overflow:hidden，使其高度包含浮动链接（frontend/src/pages/OrdersPage.tsx，
全站仅此一处 float）。窄屏下标题行增高一行，表格恢复全宽 329px；桌面布局不变。本地重测通过。
