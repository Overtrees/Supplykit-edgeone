#### 二、周转口径：从「期间流水」改到「平均库存法」

旧口径有两个错，都是**结构性**的，不是算错一个小数：

1. **分母分子不同期**：期间天数取过一次「流水最后一天」，跨月时整月分摊被摊薄；
2. **拿期末反推期初**：等于用结果证明结果，负库存永远看不见。

定案口径（用户拍板，不改一个符号）：

```
期末 = 期初 + 当月入库 − 当月出库          （不 clamp，负数就是负数）
平均 = (期初 + 期末) ÷ 2
行周转 = 平均库存 × 当月自然月天数 ÷ 当月出库
仓周转 = Σ期初…Σ出库 先合计，再按同一式子算（不是各行周转求平均）
```

| 情形 | 处理 |
|---|---|
| SKU 当月出库 = 0 | 显示「未出库」，**不计算**；但其库存仍计入仓总平均，不计入仓出库 |
| SKU 期末 < 0 | 标「负库存异常」，周转如实为负，**不兜底** |
| 仓总出库 = 0 | 「未出库」 |
| 仓平均 < 0 | 负值 + 异常标记 |
| 自然月天数 | SKU 与仓级**共用同一个** 28/29/30/31 |
| 当月未满 | 用**已过自然日**（11-04 → 4 天），前端标「月内累计 4/30」 |

同时删掉了全部兜底：`∞`、`999`、`max(0, ...)`、无销量时的假周转。**实际业务不允许以演示为名造假**。

#### 三、全链路北京时间

原来进程是 UTC，业务日期却在按天切，后果不是显示差 8 小时这么轻：

- 锁超时（`cleansing` 的 `_lock_timeout`）用 UTC 比北京时间**早 8 小时失效**，锁会提前过期；
- 效期剩余天数、库龄、`days_since_last` 全都会在每天 00:00–08:00 之间算错一天。

改法：新增 `core/clock.py`（`now_cn / today_cn / month_bounds_cn / month_days_cn / days_since_cn / elapsed_days`）
与 `utils/date.ts`（`cnNow / todayCn / daysAgoCn / daysSinceCn`），**后端 14 个文件 47 处 + 前端 7 个文件**
统一走 `+08:00`；数据库连接建立后 `SET time_zone='+08:00'`，**失败直接抛**，不静默降级。

#### 四、账期月结（甲 + B 方案）

**要解决的问题不是公式，是数据流**：库存导入把「当时的可用」写成 `beginning_stock`，而重算又是
`可用 = 期初 + Σ流水`，Σ 还不带日期 —— 每导一次库就**双算一次，单调累积**。

定案（否决了四个备选，见 `docs/decisions/0002-账期月结.md`）：

```
锚点 = 最近已结账月的期末
可用 = 锚点 + Σ(该月末之后至今的全部流水)
```

- 正常月窗口 = 一个月；漏结只会让窗口变长，**结果仍是真值**，不是兜底；
- 期初只有一个来源：**上月期末**（会计等价，不是反推）；
- 批次轨不动：`batch_opening` 存**带日期**的月初余额，上月批次跨月仍能精确命中指定批次出库；
- 数据不齐 → **拒绝结账并留痕**，绝不结假账；补导后 `POST /ledger/reclose` 补结。

新增三表 `inventory_month` / `batch_opening` / `ledger_state`（`SCHEMA_VERSION 5→6`），
`inventory` 加 `snapshot_qty`（导入快照只做对账，**不再覆盖期初**）。

**调度落点**：`edgeone.json` 的 `schedules` **maxItems 10 已占满**，加第 11 条会让整组定时任务丢路由。
所以月结嵌进最轻的 `cleanup-logs`（每日 03:05 CST），调用点放在 `_claim` **之前**（当天日志已清理也照常结账）；
4 号之后第一行就返回，**一条 SQL 都不发**。回归里加了断言锁死这条绑定 —— 挪走不报错，只会让账期永远不结。

#### 五、上线预演抓到的两个真 bug（`171cca0`）

**这类 bug 只有 dry-run 能看见**：不结账时页面一切正常，结下去就是错的期初，一路结转。

| bug | 现象 | 根因 | 修法 |
|---|---|---|---|
| 末日整天丢失 | 预演入库 338,232，库内实际 357,637 | `inbound_date <= '2026-10-31'` 对 DATETIME 只覆盖到当天 00:00:00 | 右开区间 `>= 期初日 AND < 下月 1 日` |
| bootstrap 期初偏小 | 期初取 298,550，实际应为 377,865 | `beginning_stock` 是**流水起点之前的基线**，直接当月期初漏掉 8–9 月净入 | 期初 = 基线 + `_net_before(账期起点前的净流水)` |

实测证据：2026-10-31 **单日入 19,405 / 出 23,704**，正好等于两个缺口（19,405 与 23,704），一分不差。

修正后线上预演（`GET /ledger/preview?period=2026-10`）：

```
begin 377,865   in 357,637   out 233,985   end 501,517
rows 1,003      orphan 0     days 31
available_now 376,673        diff 124,844
```

`diff` 正好等于 11 月净流水（98,515 − 223,359 = −124,844），即
**`501,517 − 124,844 = 376,673` ≡ 当前可用** —— 结账对页面数字**零跳变**，口径自洽闭环。

#### 六、推送通道：`github.com:443` 不可达

**本轮顺手修了它的一个真 bug**：`git ls-tree` 未加 `-z`，中文文件名被 quotepath 转义成
